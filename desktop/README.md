# Десктопная версия

Своё окно вокруг той же программы: установщик для Windows, ярлык в меню
«Пуск», никаких окон консоли, системный выбор файлов. Python-часть не
меняется — оболочка на [Tauri 2](https://tauri.app) запускает её и
показывает её страницу в окне.

## Как это устроено

```
Dubbing Studio_x.y.z_x64-setup.exe (~30 МБ)
  ├─ dubbing-studio.exe  оболочка Tauri (~11 МБ) с экраном первого запуска (setup/)
  ├─ uv.exe              ставит пакеты
  ├─ python/             Python 3.12 (python-build-standalone)
  └─ app/                Python-приложение (копия репозитория без окружений)
```

1. При первом запуске (и после обновления, если изменился `uv.lock` или Python)
   окно показывает экран подготовки:
   - `uv sync` создаёт окружение из встроенного Python, сам Python uv не
     скачивает и в реестр и `~\.local\bin` ничего не пишет. На машине с
     видеокартой NVIDIA добавляется `--extra cuda`, cuBLAS для Whisper, так что
     CUDA Toolkit не нужен;
   - `tools_setup.py ffmpeg` скачивает ffmpeg, если его нет в системе.

   С быстрым интернетом это занимает около 30 секунд. Движки озвучки
   ставятся потом из «Настроек» тем же uv, их окружения тоже собираются
   из встроенного Python.
2. Оболочка запускает `pipeline_ui.py --port 0 --exit-with-stdin` без окна
   консоли и открывает его страницу в окне.
3. В окне видео и образцы выбираются системным диалогом, перетащенные файлы
   приходят путями: сервер копирует их на диске, без загрузки через страницу.
4. При закрытии окна оболочка просит сервер остановить задачу и тёплую модель
   озвучки. Если оболочка упала, сервер всё равно выходит: у него закрывается
   stdin.

Где что лежит у пользователя:

| Папка | Что внутри |
|---|---|
| `%LOCALAPPDATA%\Dubbing Studio` | программа, Python и uv (заменяются при обновлении) |
| `%LOCALAPPDATA%\com.dubbingstudio.app` | окружения (`venv\`, `engines\`), кэш uv, ffmpeg, модели движков, настройки, ключи, журналы (`logs\`) |
| `Документы\Dubbing Studio` | проекты и результаты инструментов |

Python-часть узнаёт эти папки из переменных `DUB_DATA_DIR` и
`DUB_LIBRARY_DIR` (см. `paths.py`). Без них, при запуске из исходников, всё
лежит рядом с кодом, как раньше.

Если что-то пошло не так, журналы первого запуска и сервера лежат в
`%LOCALAPPDATA%\com.dubbingstudio.app\logs\` (`setup.log`, `server.log`).
Экран первого запуска открывает эту папку кнопкой «Открыть журнал».

## Сборка

Нужны [Rust](https://rustup.rs), Build Tools Visual Studio с компонентом C++,
[uv](https://docs.astral.sh/uv/) и `tauri-cli`:

```bash
cargo install tauri-cli --version "^2" --locked
```

```bash
cd desktop
```

```bash
cargo tauri build
```

`prepare.py` запускается сам перед сборкой. Он копирует приложение в
`src-tauri/app/`, а uv — в `src-tauri/binaries/`. Установщик появится в
`src-tauri/target/release/bundle/nsis/`.

Для разработки окна: `cargo tauri dev`.

## Выпуск на GitHub

Workflow `.github/workflows/desktop.yml` запускается вручную на вкладке
Actions: введите тег версии (`v0.2.0`), он соберёт установщик и приложит его к
черновику релиза. Перед этим поднимите `version` в `src-tauri/tauri.conf.json`.

## Что ещё не сделано

- Подпись установщика. Без неё Windows покажет «неизвестный издатель». Для
  открытых проектов бесплатно подписывает
  [SignPath Foundation](https://signpath.org) (нужна заявка).
- Автообновление (плагин `tauri-plugin-updater` и ключ подписи обновлений).
- macOS и Linux: оболочка собирается и там, но не проверялась.
